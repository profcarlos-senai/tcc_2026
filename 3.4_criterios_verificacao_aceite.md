## 3.4. Critérios de Verificação e Aceite

### 3.4.1. - Estratégia e Plano Geral de Testes

> **Instruções para os alunos:** Descreva em poucas linhas como cada tipo de teste será realizado no seu projeto. Caso algum teste não seja aplicável ao seu TCC, declare expressamente: *"Não se aplica ao escopo deste projeto"*.

##### Teste de Sistema:
  > *Explicação:* Avaliação do fluxo completo da aplicação (frontend + backend + banco de dados) para garantir que todas as etapas do processo funcionem de ponta a ponta sem falhas.
  * **Como faremos no projeto:** [Descreva como vão testar o sistema completo]

##### Teste de Integração:
  > *Explicação:* Validação da comunicação entre diferentes partes do código (ex.: se o backend grava e lê corretamente no banco de dados) ou com serviços de terceiros (ex.: envio de requisições de API via Postman).
  * **Como faremos no projeto:** [Descreva como vão testar as rotas de API, Postman ou banco de dados]

##### Teste de Aceite:
  > *Explicação:* Simulação de uso real junto ao cliente, professor orientador ou banca de TCC, na qual um usuário executa um roteiro de tarefas para aprovar a entrega do projeto.
  * **Como faremos no projeto:** [Descreva como será a validação com a banca/cliente]

##### Teste de Usabilidade:
  > *Explicação:* Avaliação da facilidade de navegação, clareza das telas e layout feita com potenciais usuários reais.
  * **Como faremos no projeto:** [Descreva se farão testes de interface/questionário com usuários]

##### Teste de Carga / Desempenho:
  > *Explicação:* Simulação de acessos simultâneos para verificar se a aplicação suporta múltiplos usuários ao mesmo tempo sem travar ou desacelerar.
  * **Como faremos no projeto:** [Descreva se usarão ferramentas de carga ou se não se aplica]


### 3.4.2. - Matriz de Rastreabilidade de Teste

> **Instruções para os alunos:** Vincule cada requisito do sistema (RSYS01, RSYS02, ...) ao seu respectivo método de verificação e ao critério exato que prova que a funcionalidade está pronta e correta.
> 
> **Legenda de Métodos:**
> * **[I] Inspeção:** Análise visual de código ou da documentação sem executar o programa.
> * **[D] Demonstração:** Operação visual de uma funcionalidade durante a apresentação do sistema.
> * **[A] Análise:** Cálculo, relatório ou verificação de logs e métricas.
> * **[T] Teste:** Execução formal de caso de teste com dados de entrada e validação do resultado esperado.

##### RSYS01
* **Método:** [T] Teste
* **Critério de Aceite:** Execução de requisição no Postman para o endpoint `POST /api/v1/login` retornando código HTTP 200 e token JWT válido.

##### RSYS02
* **Método:** [T] Teste
* **Critério de Aceite:** Tentar cadastrar um produto com saldo negativo e verificar se o backend bloqueia a transação exibindo a mensagem "Valor inválido".

##### RSYS03
* **Método:** [D] Demonstração
* **Critério de Aceite:** Aquecer o sensor com secador de cabelo e verificar o disparo do alarme sonoro na interface visual em até 2 segundos.
